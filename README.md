
# MailingService

MailingService — веб-приложение для управления
email-рассылками, разработанное на Django.

Приложение позволяет создавать сообщения,
управлять получателями, настраивать рассылки,
отправлять письма и отслеживать результаты отправки.

Реализованы регистрация пользователей,
разграничение прав доступа, персональная статистика
и кеширование.

## Возможности

### Получатели

- Создание, просмотр, редактирование и удаление получателей.
- Хранение email, Ф. И. О. и комментария.
- Защита от дублирования email.

### Сообщения

- Создание и редактирование email-сообщений.
- Хранение темы и текста письма.
- Использование сообщений в рассылках.

### Рассылки

- Создание рассылок с указанием времени начала и окончания.
- Выбор сообщения и нескольких получателей.
- Автоматическое определение статуса:
  - Создана
  - Запущена
  - Завершена
- Ручной запуск рассылок.
- Запрет отправки вне установленного временного интервала.
- Сохранение успешных и неуспешных попыток отправки.
- Просмотр истории попыток и ответов почтового сервера.

### Пользователи и безопасность

- Регистрация по электронной почте.
- Подтверждение email перед активацией аккаунта.
- Авторизация и выход из аккаунта.
- Восстановление пароля по электронной почте.
- Разграничение доступа к данным пользователей.
- Защита операций изменения и удаления чужих записей.

### Менеджеры

Менеджеры могут:

- Просматривать всех получателей.
- Просматривать рассылки всех пользователей.
- Просматривать список пользователей.
- Блокировать и разблокировать обычных пользователей.
- Отключать и включать рассылки.

При этом менеджеры не могут редактировать
или удалять чужие записи через интерфейс приложения.

### Статистика

Для каждого пользователя доступна статистика:

- Количество созданных рассылок.
- Общее количество попыток отправки.
- Количество успешных попыток.
- Количество неуспешных попыток.
- Количество успешно отправленных писем.
- Подробная статистика по каждой рассылке.

### Кеширование

Реализованы два уровня кеширования:

- Серверное: встроенный Django LocMemCache.
- Клиентское: WhiteNoise и HTTP Cache-Control.

Статистика кешируется отдельно для каждого пользователя.
При изменении результатов отправки кеш сбрасывается.

## Установка и запуск

Инструкция приведена для Windows и PowerShell.

### 1. Клонирование репозитория

Склонируйте проект с GitHub и перейдите
в его директорию.

### 2. Создание виртуального окружения

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 3. Установка зависимостей

```powershell
python -m pip install -r requirements.txt
```

### 4. Настройка PostgreSQL

Установите PostgreSQL и создайте базу данных:

```sql
CREATE DATABASE mailing_service;
```

Пользователь PostgreSQL должен иметь необходимые
права для работы с этой базой данных.

### 5. Настройка переменных окружения

Создайте файл `.env` на основе `.env.example`:

```powershell
Copy-Item .env.example .env
```

Укажите в `.env` действующие параметры PostgreSQL.

Сгенерируйте секретный ключ Django:

```powershell
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

Скопируйте полученное значение в переменную
`SECRET_KEY` файла `.env`.

Настоящий `.env` не должен публиковаться в GitHub.

### 6. Применение миграций

```powershell
python manage.py migrate
```

### 7. Создание суперпользователя

```powershell
python manage.py createsuperuser
```

### 8. Сборка статических файлов

```powershell
python manage.py collectstatic --noinput
```

### 9. Запуск сервера

```powershell
python manage.py runserver
```

После запуска приложение доступно по адресу:

http://127.0.0.1:8000/

## Основные страницы

- `/` — главная страница.
- `/accounts/register/` — регистрация.
- `/accounts/login/` — авторизация.
- `/recipients/` — управление получателями.
- `/messages/` — управление сообщениями.
- `/mailings/` — управление рассылками.
- `/statistics/` — персональная статистика.
- `/manager/` — панель менеджера.
- `/admin/` — административная панель Django.

## Настройка роли менеджера

Для предоставления пользователю прав менеджера:

1. Войдите в Django Admin под суперпользователем.
2. Создайте группу с названием `Менеджеры`.
3. Добавьте нужного пользователя в эту группу.

Пользователь из группы `Менеджеры` получит
доступ к панели управления `/manager/`.

Суперпользователь также имеет доступ
к панели менеджера.

## Отправка электронных писем

В режиме разработки используется консольный
почтовый backend Django.

Письма выводятся в терминал вместо фактической
отправки на электронные адреса получателей.

Это позволяет тестировать отправку, регистрацию,
подтверждение аккаунтов и восстановление паролей
без подключения реального SMTP-сервера.

Для реальной отправки потребуется настроить
соответствующий почтовый backend.

## Кеширование

### Серверное

Для кеширования общей статистики используется
стандартный backend Django LocMemCache.

Время хранения данных — 300 секунд.

Ключи кеша разделены по идентификаторам
пользователей.

После изменения результатов отправки
соответствующие данные кеша сбрасываются.

LocMemCache предназначен для локальной разработки.
Он хранит данные в памяти отдельного процесса.

### Клиентское

WhiteNoise обслуживает статические файлы
и устанавливает HTTP-заголовки кеширования.

В режиме разработки обычные статические файлы
кешируются браузером в течение 60 секунд.

Для статических файлов также используются
сжатие и хеширование имён.

Персональная страница статистики исключена
из HTTP-кеширования.

## Безопасность

- Конфиденциальные настройки хранятся в `.env`.
- `.env` исключён из Git.
- Пользователи получают доступ только к разрешённым данным.
- Изменение чужих записей ограничено на уровне Django Views.
- Отправка отключённой рассылки запрещена.

Проект настроен для локальной разработки.
Перед публичным развёртыванием необходимо
отключить DEBUG, настроить разрешённые хосты,
почтовый сервер, HTTPS и другие параметры безопасности.
